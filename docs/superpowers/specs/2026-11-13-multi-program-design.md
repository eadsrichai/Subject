# รองรับหลายสาขา (ปวช. และ ปวส.) — เอกสารออกแบบ

วันที่: 2026-11-13 · สถานะ: รอผู้ใช้ตรวจ · ต่อยอดจาก [2026-11-12-course-database-design.md](2026-11-12-course-database-design.md)

## 1. เป้าหมาย

ระบบรุ่นแรกรองรับเฉพาะ **ปวส. 2567 สาขาวิชาเทคโนโลยีสารสนเทศ (31901)** งานนี้ทำให้นำเข้าและแสดงหลักสูตร **ปวช. และ ปวส. 2567 สาขาอื่น ๆ** ของ สอศ. ได้ (เอกสารเดิมระบุ "การรองรับหลายหลักสูตร" ไว้นอกขอบเขต เอกสารนี้ยกเลิกข้อนั้น)

สิ่งที่ผู้ใช้กำหนด:

- นำเข้าโดย **ผู้พัฒนาผ่านคำสั่ง** ไม่มีหน้าอัปโหลด PDF
- วิชาที่ใช้ร่วมหลายสาขา **เก็บเนื้อหาชุดเดียว** แต่ละสาขาจัดวิชาลงหมวดของตัวเอง
- ผู้ใช้ทั่วไป **เลือกสาขาก่อน** แล้วเห็นหน้ารายวิชา แดชบอร์ด พิมพ์ และ Excel ของสาขานั้น

สมมติฐาน (ผู้ใช้ยืนยันแล้ว):

- สิทธิ์ผู้ใช้ไม่แยกตามสาขา ADMIN และ STAFF แก้ได้ทุกสาขา
- มีหลักสูตรปีเดียว (2567)
- ระบบยังไม่ขึ้นใช้งานจริง ไม่ต้องคง URL เก่า

ถือว่าสำเร็จเมื่อ:

1. นำเข้า `Data/ปวช-เทคโนโลยีสารสนเทศ-21901.pdf` ได้โดยไม่ต้องเขียนโค้ดเฉพาะเล่ม จำนวนวิชาและหมวดตรงกับตารางโครงสร้างในเล่ม
2. ข้อมูล 31901 เดิมอยู่ครบ รวมถึงที่แก้ผ่านเว็บ และ `31901.json` ที่แยกใหม่ตรงกับ `courses.json` เดิม
3. ทุกความสามารถเดิมของหน้าเว็บใช้ได้ภายใต้สาขาที่เลือก

### นอกขอบเขต

อัปโหลด PDF ผ่านเว็บ · หลายปีหลักสูตร · สิทธิ์ตามสาขา · redirect URL เก่า · คำอธิบายวิชาแกนกลางที่อยู่ "ตามเอกสารนอกเล่ม"

## 2. ข้อมูลต้นทาง: เล่ม ปวช. 21901 เทียบกับ ปวส. 31901

| | ปวส. 31901 | ปวช. 21901 |
|---|---|---|
| จำนวนหน้า | 139 | 81 |
| ตารางโครงสร้าง | 37–47 | 14–24 |
| คำอธิบายรายวิชา | 48–106 | 28–81 |
| รหัสวิชา | 3xxxx-xxxx | 2xxxx-xxxx |
| หมวดปรับพื้นฐานวิชาชีพ | มี | ไม่มี |
| เลขหมวด | `1` | `1.` (มีจุดต่อท้าย) |
| คำอธิบายวิชาแกนกลาง | มีในเล่ม | "รายละเอียดคำอธิบายรายวิชา ตามเอกสารนอกเล่ม" |
| ข้อความแม่แบบตกค้าง | — | "(เว้นระยะอักษร 10)" ระหว่างหัวข้อ |

เหมือนกัน: ชื่อหัวข้อ 5 ส่วนของคำอธิบายรายวิชา, อาการ "า" เป็น "ำ" ในตัวหนา, คอลัมน์ ท-ป-น ชิดขวา (x ≈ 496–516), รหัสวิชาบางแถวถูกหั่นเป็นหลายชิ้น ("20000-20 | 03")

รหัสวิชา ปวช. กับ ปวส. ไม่ชนกัน ในระดับเดียวกันวิชาร่วมใช้รหัสเดียวกัน (20000-* ทุกสาขา ปวช., 21900-* ทุกสาขาในประเภทวิชาเดียวกัน)

## 3. โครงสร้างฐานข้อมูล

```prisma
enum Level { PVC PVS }          // ปวช. / ปวส.

model Program {
  id         Int    @id @default(autoincrement())
  code       String @unique       // "31901", "21901"
  level      Level
  name       String               // "เทคโนโลยีสารสนเทศ"
  typeName   String               // ประเภทวิชา
  year       Int    @default(2567)
  sortOrder  Int    @default(0)
  categories Category[]
  courses    ProgramCourse[]
}

model Category {
  // ช่องเดิมทั้งหมด ยกเว้น code ไม่ unique ทั้งตารางแล้ว
  programId Int
  program   Program @relation(fields: [programId], references: [id], onDelete: Cascade)
  placements ProgramCourse[]
  @@unique([programId, code])
}

model Course {
  // ช่องเดิมทั้งหมด ยกเว้นลบ categoryId และ sourcePage
  sourceProgramCode String?       // เล่มที่เป็นเจ้าของเนื้อหา; null = สร้างผ่านเว็บ
  placements ProgramCourse[]
}

model ProgramCourse {
  programId  Int
  courseId   Int
  categoryId Int
  sourcePage Int?
  program    Program  @relation(fields: [programId], references: [id], onDelete: Restrict)
  course     Course   @relation(fields: [courseId], references: [id], onDelete: Cascade)
  category   Category @relation(fields: [categoryId], references: [id], onDelete: Restrict)
  @@id([programId, courseId])
  @@index([categoryId])
}
```

กติกา:

- `ProgramCourse.categoryId` ต้องเป็นหมวดของ `programId` เดียวกัน ตรวจในโค้ด (`lib/course-admin.ts`, seed)
- `needsReview`, `reviewNote`, `editedAt` อยู่ที่ `Course` (เรื่องเนื้อหา) การย้ายหมวดไม่ตั้ง `editedAt`
- หมวด "ยังไม่จัดหมวด" (`NONE`) มีแยกในแต่ละสาขา
- ลบวิชา → ตำแหน่งในทุกสาขาหายตาม (Cascade)
- ลบสาขา → ทำได้เมื่อไม่มี `ProgramCourse` เหลือ (Restrict) หมวดของสาขาถูกลบตาม (Cascade)
- ลบหมวด → ทำไม่ได้ถ้ายังมีวิชาอยู่ในหมวด (เหมือนเดิม)
- วิชาที่ไม่มีตำแหน่งในสาขาใดบันทึกได้ แสดงเฉพาะในผลค้นหาข้ามสาขาและหน้าผู้ดูแล

### Migration ข้อมูลเดิม

migration ไฟล์เดียว (SQL) ไม่ต้อง seed ใหม่:

1. สร้างตาราง `Program` และใส่แถว `31901` (PVS, "เทคโนโลยีสารสนเทศ", "อุตสาหกรรมดิจิทัลและเทคโนโลยีสารสนเทศ")
2. เพิ่ม `Category.programId` = id ของ 31901 ทุกแถว แล้วเปลี่ยน unique จาก `code` เป็น `(programId, code)`
3. สร้าง `ProgramCourse` จาก `Course.categoryId` และ `Course.sourcePage` ทุกแถว
4. ตั้ง `Course.sourceProgramCode = '31901'` ให้วิชาที่มี `sourcePage` (มาจาก PDF) ที่เหลือเป็น null
5. ลบ `Course.categoryId` และ `Course.sourcePage`

db test สร้างข้อมูลแบบ schema เก่า รัน migration แล้วเทียบผลทีละวิชา (หมวด หน้า `editedAt` ธงต้องตรวจ)

## 4. ขั้นตอนนำเข้า

### ไฟล์ทะเบียน `Data/programs.json` (commit)

```json
[
  { "code": "31901", "level": "PVS", "name": "เทคโนโลยีสารสนเทศ",
    "typeName": "อุตสาหกรรมดิจิทัลและเทคโนโลยีสารสนเทศ",
    "pdf": "31901v7_18_10_68.pdf", "pages": [37, 106] },
  { "code": "21901", "level": "PVC", "name": "เทคโนโลยีสารสนเทศ",
    "typeName": "อุตสาหกรรมดิจิทัลและเทคโนโลยีสารสนเทศ",
    "pdf": "ปวช-เทคโนโลยีสารสนเทศ-21901.pdf", "pages": [14, 81] }
]
```

ตรวจด้วย zod ตอนโหลด: รหัส 5 หลักไม่ซ้ำ, ระดับเป็น PVC/PVS, `pages[0] ≤ pages[1]` ผิดข้อใดหยุดทันทีพร้อมข้อความชี้ตำแหน่ง ลำดับในไฟล์คือ `sortOrder` และลำดับการ seed

### แยกข้อมูล `npm run extract -- [รหัสสาขา…]`

- ไม่ระบุรหัส = ทุกสาขาที่มีไฟล์ PDF อยู่ (ข้ามสาขาที่ไม่มีไฟล์พร้อมแจ้ง)
- ผล: `Data/extracted/<code>.json` และ `<code>.report.txt` (`courses.json` / `report.txt` เดิม → `31901.*`)
- ตัวแยก (`scripts/pdf/parse.ts`) ปรับ:
  - ช่วงหน้ามาจากไฟล์ทะเบียน
  - `parseCategoryHeading` รับเลขหมวดที่มีจุดต่อท้าย
  - หมวด PRE สร้างเฉพาะเมื่อพบป้าย "รายวิชาปรับพื้นฐานวิชาชีพ"
  - ตัดบรรทัด "(เว้นระยะอักษร …)" ก่อนแยกส่วน
  - หมวดรากที่ไม่มีบล็อกคำอธิบายในเล่ม ไม่ติดธง "ไม่พบคำอธิบาย" (ใช้กลไก `rootsWithDescriptions` ที่มีอยู่)
- รายงานขึ้นต้นด้วยจำนวนวิชาต่อหมวด เพื่อเทียบกับตารางโครงสร้างในเล่มด้วยตา

### นำเข้า `npx prisma db seed [-- --force]`

อ่านไฟล์ทะเบียน แล้วทำทีละสาขาตามลำดับ ข้ามสาขาที่ยังไม่มีไฟล์ `extracted/<code>.json`:

1. **สาขา** — สร้างถ้ายังไม่มี มีแล้วไม่แตะ (ไม่มีตราการแก้ จึงถือว่าอาจแก้ผ่านเว็บ) ยกเว้น `force`
2. **หมวด** — สร้างเฉพาะหมวดที่ยังไม่มีในสาขา ยกเว้น `force`
3. **เนื้อหาวิชา**
   - ยังไม่มี → สร้าง, `sourceProgramCode` = สาขานี้
   - มีแล้วและสาขานี้เป็นเจ้าของ → อัปเดตเนื้อหา เว้นแต่ `editedAt` ตั้งอยู่ (และไม่ `force`)
   - มีแล้วแต่เจ้าของเป็นสาขาอื่น/null → เติมเฉพาะช่องที่ว่าง; ช่องที่มีค่าทั้งสองฝั่งแต่ต่างกัน (เทียบหลังยุบช่องว่าง) → ไม่ทับ, ติด `needsReview`, ต่อท้าย `reviewNote` "เนื้อหาต่างจากหลักสูตร <code>: <ช่อง>"
4. **ตำแหน่งในสาขา** — สร้างเฉพาะที่ยังไม่มี ยกเว้น `force`
5. วิชาที่ไม่อยู่ใน PDF แล้ว ไม่ลบ

สรุปท้ายการรันแยกตามสาขา: เพิ่ม / อัปเดต / ใช้ร่วม / เติมช่องว่าง / เนื้อหาไม่ตรง / ข้าม (แก้ผ่านเว็บ)

## 5. หน้าเว็บสาธารณะ

| URL | เนื้อหา |
|---|---|
| `/` | รายชื่อหลักสูตรแบ่งกลุ่ม ปวช. / ปวส.: ชื่อ ประเภทวิชา รหัส จำนวนวิชา + ช่องค้นหาข้ามสาขา |
| `/p/[code]` | หน้ารายวิชาของสาขา (ความสามารถเดิมของ `/`) หมวดใน dropdown เฉพาะของสาขา |
| `/p/[code]/dashboard` | แดชบอร์ดของสาขา (เดิม `/dashboard`) |
| `/p/[code]/print` | หน้าพิมพ์ของสาขา (เดิม `/print`) |
| `/api/export?program=<code>&…` | Excel ตามตัวกรอง ชื่อไฟล์มีรหัสสาขา |
| `/search?q=&credits=&page=` | ค้นหาข้ามสาขา แต่ละวิชามีป้ายสาขา ("ปวช. เทคโนโลยีสารสนเทศ") |
| `/courses/[code]` | รายละเอียดวิชา + ตาราง "อยู่ในหลักสูตร" (ระดับ สาขา หมวด) · `?from=<code>` แสดงลิงก์กลับสาขา |

- ชื่อเว็บ: "ฐานข้อมูลรายวิชา หลักสูตร 2567" หน้าในสาขาแสดงชื่อสาขาและระดับใต้ชื่อเว็บ ข้อความสาขาที่ฝังในโค้ด (`app/layout.tsx`, `app/(public)/layout.tsx`, `print/page.tsx`) ดึงจากฐานข้อมูลแทน
- รหัสสาขาไม่มีจริง → 404 ภาษาไทย; `category` ที่ไม่ใช่ของสาขา → เพิกเฉยตัวกรอง; `/` แสดงรายชื่อหลักสูตรเสมอแม้มีสาขาเดียว
- `lib/courses.ts`: `CourseFilter` เพิ่ม `programId: number | null` (null = ข้ามสาขา); สถิติแดชบอร์ดรับ `programId`; เพิ่ม `listPrograms()` และ `getProgramByCode()`
- `/dashboard` และ `/print` เดิมจะเป็น 404

## 6. หน้าผู้ดูแล

สิทธิ์: หน้าใหม่และหน้าที่แก้ในส่วนนี้ใช้ได้ทั้ง ADMIN และ STAFF (เหมือนหน้าหมวด) ส่วนหน้าจัดการผู้ใช้ยังเป็น ADMIN เท่านั้น

- **`/admin/programs`** (ใหม่) — ตาราง: ระดับ รหัส ชื่อ ประเภทวิชา จำนวนวิชา ลำดับ · เพิ่มสาขาเองได้ · แก้ได้ทุกช่องยกเว้นรหัส · ลบได้เมื่อไม่มีวิชา ไม่งั้นแจ้ง "ยังมี N วิชาในสาขานี้"
- **`/admin/categories?program=<code>`** — เลือกสาขาด้านบน (ค่าเริ่มต้น = สาขาแรก) · รหัสหมวดห้ามซ้ำในสาขา · หมวดแม่ต้องอยู่สาขาเดียวกัน
- **`/admin/courses`** — ตัวกรองสาขาเพิ่ม (ใช้ร่วมกับ "ต้องตรวจ" และค้นหา) · ป้ายสาขาในตาราง
- **ฟอร์มวิชา** — ช่องเนื้อหาเดิม + ส่วน "อยู่ในหลักสูตร": แถว [สาขา ▾][หมวด ▾][ลบ] และ "+ เพิ่มสาขา" (client component กรองหมวดตามสาขา)
  - server ตรวจ: สาขาละแถวเดียว, หมวดเป็นของสาขานั้น; ข้อผิดพลาดรายแถว (คีย์ `placements.<i>`)
  - ไม่มีแถวเลย → บันทึกได้ พร้อมคำเตือน "วิชานี้จะไม่แสดงในหน้ารายวิชาของสาขาใด"
  - ใช้ร่วม > 1 สาขา → แถบเตือน "เนื้อหาวิชานี้ใช้ร่วมกับ N สาขา แก้แล้วมีผลทุกสาขา"
  - บันทึกเนื้อหาและตำแหน่งทั้งหมดใน transaction เดียว (แทนที่ชุดตำแหน่งเดิมทั้งชุด); เนื้อหาตั้ง `editedAt` เหมือนเดิม
- **`/admin`** — จำนวนวิชาและจำนวน "ต้องตรวจ" แยกตามสาขา ลิงก์ไปหน้ารายวิชาที่กรองแล้ว
- ผู้ใช้และบัญชีของฉัน — ไม่เปลี่ยน

## 7. การทดสอบ

| ชั้น | ครอบคลุม |
|---|---|
| unit | ตัวแยกด้วยบรรทัดตัวอย่างจากเล่ม ปวช. (หมวดมีจุด, ไม่มี PRE, ข้อความแม่แบบ, หมวดไม่มีคำอธิบาย, รหัสถูกหั่น) · โหลด/ตรวจไฟล์ทะเบียน · validation ตำแหน่งในสาขา |
| db | migration ข้อมูลเดิม · seed สองสาขามีวิชาร่วม (เจ้าของอัปเดต, เติมช่องว่าง, เนื้อหาต่างได้ธง, ตำแหน่ง/หมวด/สาขาที่แก้ไม่ถูกทับ, force) · ค้นหาในสาขาและข้ามสาขา · หมวดสาขาอื่นถูกเพิกเฉย · ลบสาขาที่มีวิชาไม่ได้ · บันทึกวิชา+ตำแหน่ง atomic · หมวดผิดสาขาถูกปฏิเสธ |
| e2e | เทสต์เดิม 24 ตัวย้ายไป `/p/<code>` และผ่าน · `/` เห็นสองระดับ · ค้นหาข้ามสาขามีป้าย · รายละเอียดวิชาแสดงหลายสาขา · ผู้ดูแลเพิ่มวิชาเข้าสาขาที่สองแล้วเห็นในสาขานั้น · รหัสสาขาไม่มีจริง → 404 |
| ข้อมูลจริง | `31901.json` ตรงกับ `courses.json` เดิม · `21901.report.txt` จำนวนวิชาต่อหมวดตรงกับตารางโครงสร้าง |
