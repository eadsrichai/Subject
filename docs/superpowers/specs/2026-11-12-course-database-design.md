# ระบบฐานข้อมูลรายวิชา — เอกสารออกแบบ

วันที่: 2026-11-12 · สถานะ: รอผู้ใช้ตรวจ

## 1. เป้าหมาย

เว็บสำหรับค้นหาและดูแลข้อมูลรายวิชาของ **หลักสูตรประกาศนียบัตรวิชาชีพชั้นสูง (ปวส.) พุทธศักราช 2567 สาขาวิชาเทคโนโลยีสารสนเทศ** โดยนำข้อมูลตั้งต้นจาก `Data/31901v7_18_10_68.pdf` เข้าฐานข้อมูลครั้งเดียว

ผู้ใช้สองกลุ่ม:

- **บุคคลทั่วไป** (ไม่ล็อกอิน): ค้นหา กรอง ดูรายละเอียดรายวิชา ดูแดชบอร์ดสรุป ส่งออก Excel/PDF
- **ผู้ดูแล** (ล็อกอิน): แก้ไขข้อมูลรายวิชาและหมวดวิชา จัดการบัญชีผู้ใช้

ถือว่าสำเร็จเมื่อ: รายวิชาทุกวิชาในหน้า 37–106 ของ PDF อยู่ในฐานข้อมูลพร้อมหมวดที่ถูกต้อง ค้นหาเจอด้วยรหัสหรือชื่อ และผู้ดูแลแก้ไขข้อมูลได้โดยไม่ต้องแตะโค้ด

### นอกขอบเขต

- ผู้สอน ตารางเรียน ภาคเรียนที่เปิดสอน (ไม่มีใน PDF และผู้ใช้ยืนยันว่าไม่ต้องการ)
- อัปโหลด/นำเข้า PDF ผ่านหน้าเว็บ
- การรองรับหลายหลักสูตร — ทำแล้วตาม `docs/superpowers/specs/2026-11-13-multi-program-design.md`
- เนื้อหาส่วนอื่นของเล่ม: หลักการ หลักเกณฑ์ มาตรฐานวิชาชีพ ผลลัพธ์การเรียนรู้รายปี (หน้า 14–36) และหน้าที่เป็นภาพสแกน (4–13, 107–139)
- การนำขึ้นเซิร์ฟเวอร์จริง รุ่นแรกรันบนเครื่องผู้พัฒนา

## 2. ข้อมูลต้นทาง (ผลสำรวจ PDF)

139 หน้า ส่วนที่ใช้มีสองส่วน ซึ่งกล่าวถึงวิชาชุดเดียวกัน:

| ส่วน | หน้า | ให้ข้อมูล |
|---|---|---|
| โครงสร้างหลักสูตร | 37–47 และตารางนำหน้าแต่ละหมวดในส่วนถัดไป | ลำดับชั้นหมวด/กลุ่ม หน่วยกิตขั้นต่ำ รหัส ชื่อไทย ชื่ออังกฤษ ท-ป-น |
| คำอธิบายรายวิชา | 48–106 | ต่อหนึ่งวิชา: อ้างอิงมาตรฐาน, ผลลัพธ์การเรียนรู้ระดับรายวิชา, จุดประสงค์รายวิชา, สมรรถนะรายวิชา, คำอธิบายรายวิชา |

ลำดับชั้นที่พบ:

- รายวิชาปรับพื้นฐานวิชาชีพ (15 หน่วยกิต)
- 1 หมวดวิชาสมรรถนะแกนกลาง (≥15) → 1.1 ภาษาและการสื่อสาร, 1.2 การคิดและการแก้ปัญหา, 1.3 สังคมและการดำรงชีวิต
- 2 หมวดวิชาสมรรถนะวิชาชีพ (≥60) → 2.1 วิชาชีพพื้นฐาน, 2.2 วิชาชีพเฉพาะ
- 3 หมวดวิชาเลือกเสรี (≥5)
- 4 กิจกรรมเสริมหลักสูตร

ความเสียหายของข้อความและวิธีจัดการ:

| อาการ | ขอบเขต | วิธีจัดการ |
|---|---|---|
| วรรณยุกต์/การันต์เป็นอักขระ PUA (U+F700–F717) | หน้า 3, 45–47, 85, 94, 106 | แปลงกลับด้วยตารางจับคู่ตายตัว |
| สระอำแยกเป็น `ํ`+`า` หรือมีช่องว่างคั่น ("ค ำ") | ประปราย | normalize |
| "า" กลายเป็น "ำ" ในตัวหนา ("กำรเป็นผู้ประกอบกำร") | หัวข้อและชื่อวิชาในหน้าคำอธิบายรายวิชา | ใช้ชื่อจากตารางโครงสร้าง; หัวข้อใช้เป็นตัวแบ่งส่วนเท่านั้น ไม่เก็บ |
| ช่องว่างแทรกกลางคำ รหัส/ท-ป-น ถูกหั่น | ทั่วไป | ต่อชิ้นข้อความตามพิกัด x แล้วตรวจรูปแบบด้วย regex |
| ตัวอักษรหายจริง | หน้า 25 (ไม่ใช่ข้อมูลรายวิชา) และคำสะกดผิดประปราย | ไม่นำเข้าหน้า 25; ที่เหลือแก้ผ่านหน้าผู้ดูแล |

## 3. สถาปัตยกรรม

แอป Next.js ตัวเดียว (App Router, TypeScript) เชื่อม PostgreSQL 16 ที่รันใน Docker

- UI: Tailwind CSS + shadcn/ui, ภาษาไทยทั้งหมด
- ข้อมูล: Prisma (schema + migration + seed)
- อ่านข้อมูล: Server Components เรียกฟังก์ชันใน `lib/courses.ts` โดยตรง
- เขียนข้อมูล: Server Actions ทุกตัวผ่าน `lib/authz.ts` ก่อน
- ยืนยันตัวตน: Auth.js แบบ Credentials (อีเมล + รหัสผ่าน bcrypt), session แบบ JWT เก็บ role

หน่วยย่อยและหน้าที่:

| หน่วย | หน้าที่ | พึ่งพา |
|---|---|---|
| `scripts/pdf/normalize-thai.mjs` | แก้ข้อความไทยที่เพี้ยน (ฟังก์ชันล้วน) | – |
| `scripts/pdf/extract.mjs` | PDF → `Data/extracted/courses.json` + รายงาน | pdfjs-dist, normalize-thai |
| `prisma/seed.ts` | JSON → ฐานข้อมูล, สร้าง ADMIN แรก | Prisma |
| `lib/courses.ts` | ค้นหา/กรอง/แบ่งหน้า/สถิติ | Prisma |
| `lib/authz.ts` | `requireRole(role)` จุดเดียวสำหรับตรวจสิทธิ์ | Auth.js |
| `lib/export.ts` | ผลค้นหา → ไฟล์ xlsx | exceljs, lib/courses |

## 4. โมเดลข้อมูล

```
Category
  id, code (เช่น "1", "1.1", "PRE"), name, minCredits?, note?, sortOrder
  parentId? → Category        -- ต้นไม้ หมวด → กลุ่ม (ลึกได้ตามที่ PDF มี)

Course
  id, code (unique เช่น "31900-0001")
  nameTh, nameEn
  theoryHours, practiceHours, credits     -- ท-ป-น
  standardRef?          -- อ้างอิงมาตรฐาน
  learningOutcome?      -- ผลลัพธ์การเรียนรู้ระดับรายวิชา
  objectives?           -- จุดประสงค์รายวิชา
  competencies?         -- สมรรถนะรายวิชา
  description?          -- คำอธิบายรายวิชา
  categoryId → Category
  sourcePage?           -- หน้า PDF ที่มาของคำอธิบาย
  needsReview (bool)    -- parser ไม่มั่นใจ ให้ผู้ดูแลตรวจ
  createdAt, updatedAt

User
  id, email (unique), name, passwordHash, role (ADMIN | STAFF), active
```

- ฟิลด์ข้อความยาวเก็บเป็น text ธรรมดา คงการขึ้นบรรทัด/เลขข้อไว้
- ลบ Category ที่ยังมีรายวิชาหรือหมวดย่อยไม่ได้
- index แบบ trigram (`pg_trgm`) บน `code`, `nameTh`, `nameEn`

## 5. การนำเข้าข้อมูล

1. `npm run extract` — อ่านหน้า 37–106 จัดข้อความเป็นบรรทัดตามพิกัด, normalize, แล้ว
   - จากตาราง: จับแถว `รหัส | ชื่อไทย | ท-ป-น` กับบรรทัดชื่ออังกฤษถัดไป และจำหัวข้อหมวด/กลุ่มล่าสุดเพื่อผูกหมวด
   - จากคำอธิบาย: เริ่มวิชาใหม่เมื่อพบบรรทัดขึ้นต้นด้วยรหัสวิชาตามด้วยหัวข้อ "อ้างอิงมาตรฐาน" แล้วแบ่งเนื้อหาตามหัวข้อห้าหัวข้อ
   - รวมสองแหล่งด้วยรหัสวิชา
2. เขียน `Data/extracted/courses.json` และ `Data/extracted/report.txt` ที่ระบุ: จำนวนวิชา, วิชาที่มีในตารางแต่ไม่มีคำอธิบาย (และกลับกัน), วิชาที่ ท-ป-น สองแหล่งไม่ตรงกัน, วิชาที่ขาดหัวข้อ วิชาเหล่านี้ถูกตั้ง `needsReview`
3. ผู้ใช้เปิดดู JSON/รายงานได้ก่อนนำเข้า
4. `npx prisma db seed` — upsert ตามรหัสวิชา รันซ้ำได้ **แต่ไม่เขียนทับวิชาที่ถูกแก้ผ่านหน้าเว็บแล้ว** (ตรวจจาก `updatedAt > createdAt`) เว้นแต่ส่ง `--force`

วิชาที่ปรากฏซ้ำในหลายตาราง (เช่น ตารางสรุปและตารางนำหน้าหมวด) นับเป็นวิชาเดียว

## 6. หน้าสาธารณะ

| เส้นทาง | เนื้อหา |
|---|---|
| `/` | ช่องค้นหา (รหัส ชื่อไทย ชื่ออังกฤษ คำอธิบาย), ตัวกรองหมวด/กลุ่ม และหน่วยกิต, ตารางผลลัพธ์แบ่งหน้า 20 รายการ, ปุ่มส่งออก สถานะทั้งหมดอยู่ใน query string |
| `/courses/[code]` | รายละเอียดครบทุกหัวข้อ เส้นทางหมวด (breadcrumb) ปุ่มพิมพ์ |
| `/dashboard` | จำนวนวิชาและหน่วยกิตรวมต่อหมวด, การกระจายตามจำนวนหน่วยกิต, สัดส่วนชั่วโมงทฤษฎี/ปฏิบัติ, หน่วยกิตขั้นต่ำตามโครงสร้าง |
| `/api/export?…` | ไฟล์ xlsx ของผลค้นหาตามตัวกรองเดียวกับหน้า `/` (ทุกหน้า ไม่ใช่เฉพาะหน้าปัจจุบัน) |
| `/print?…` | รายการแบบพร้อมพิมพ์ ใช้ "บันทึกเป็น PDF" ของเบราว์เซอร์ |

ส่งออก PDF ใช้การพิมพ์ของเบราว์เซอร์แทนไลบรารีสร้าง PDF เพื่อให้ภาษาไทยตัดคำและวางสระถูกต้อง

กราฟใช้ Recharts ทุกกราฟมีตารางตัวเลขประกอบ

## 7. หน้าผู้ดูแล

| เส้นทาง | สิทธิ์ | เนื้อหา |
|---|---|---|
| `/login` | – | อีเมล + รหัสผ่าน |
| `/admin` | ADMIN, STAFF | สรุป และรายการวิชาที่ `needsReview` |
| `/admin/courses`, `/admin/courses/[id]` | ADMIN, STAFF | เพิ่ม/แก้ไข/ลบรายวิชา, ยกเลิกเครื่องหมาย needsReview |
| `/admin/categories` | ADMIN, STAFF | เพิ่ม/แก้ไข/ลบ/จัดลำดับหมวดและกลุ่ม |
| `/admin/users` | ADMIN | เพิ่มผู้ใช้ เปลี่ยนบทบาท รีเซ็ตรหัสผ่าน ปิดการใช้งาน |
| `/admin/account` | ADMIN, STAFF | เปลี่ยนรหัสผ่านของตนเอง |

กฎสิทธิ์:

- middleware กันผู้ไม่ล็อกอินออกจาก `/admin/*`; Server Action ทุกตัวตรวจ role ซ้ำด้วย `requireRole` (ไม่พึ่ง middleware อย่างเดียว)
- STAFF เรียก action จัดการผู้ใช้แล้วถูกปฏิเสธ
- ADMIN ปิดการใช้งานหรือลดบทบาทตนเองไม่ได้ และระบบต้องเหลือ ADMIN ที่ใช้งานได้อย่างน้อยหนึ่งคน
- ผู้ใช้ที่ถูกปิดการใช้งานล็อกอินไม่ได้
- ไม่มีหน้าสมัครสมาชิก ADMIN แรกสร้างจาก `ADMIN_EMAIL`/`ADMIN_PASSWORD` ใน `.env` ตอน seed

## 8. การจัดการข้อผิดพลาด

- ฟอร์ม: ตรวจด้วย zod ฝั่งเซิร์ฟเวอร์ แสดงข้อความภาษาไทยใต้ช่องที่ผิด; รหัสวิชาซ้ำแจ้งชัดเจน
- ล็อกอินผิด: ข้อความเดียวกันไม่ว่าอีเมลหรือรหัสผ่านผิด
- ไม่พบรายวิชา: หน้า 404 ภาษาไทย; ค้นหาไม่เจอ: ข้อความว่างพร้อมปุ่มล้างตัวกรอง
- ฐานข้อมูลเชื่อมไม่ได้: หน้า error ที่บอกให้ตรวจว่า Docker รันอยู่
- extract: แถวที่ parse ไม่ได้ไม่ทำให้สคริปต์ล้ม แต่ถูกบันทึกในรายงาน; สคริปต์จบด้วยรหัสผิดพลาดถ้าได้วิชาเป็นศูนย์

## 9. การทดสอบ

- **Vitest (หน่วย):** `normalize-thai` (PUA, สระอำ, ช่องว่าง), ตัวจับแถวตารางและตัวแบ่งหัวข้อของ extract โดยใช้บรรทัดจริงจาก PDF เป็น fixture, ตัวสร้างเงื่อนไขค้นหา, กฎสิทธิ์ใน `authz` และกฎ ADMIN คนสุดท้าย
- **Vitest (ฐานข้อมูลจริง):** seed รันซ้ำแล้วจำนวนแถวไม่เพิ่ม และไม่ทับวิชาที่แก้แล้ว
- **Playwright:** ค้นหา+กรอง → เปิดรายละเอียด; ดาวน์โหลด xlsx แล้วอ่านกลับเทียบจำนวนแถว; ล็อกอิน STAFF แก้วิชาได้แต่เข้า `/admin/users` ไม่ได้; ADMIN เพิ่มผู้ใช้; ผู้ไม่ล็อกอินถูกส่งไป `/login`
- **ตรวจด้วยมือหลังนำเข้า:** จำนวนวิชาต่อหมวดเทียบกับ PDF และสุ่มเทียบ 10 วิชากับต้นฉบับ

## 10. การรันบนเครื่อง

```
docker compose up -d          # Postgres
npx prisma migrate dev
npm run extract               # PDF → Data/extracted/
npx prisma db seed
npm run dev                   # http://localhost:3000
```

ค่าใน `.env`: `DATABASE_URL`, `AUTH_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` (มี `.env.example`)
